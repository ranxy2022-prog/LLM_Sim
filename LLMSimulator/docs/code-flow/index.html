阅读方式

知道从哪里来，也知道回哪里去。

每列是一层函数流程，从上向下阅读。调用节点上的「展开子流程」连接到右侧下一列；顶部路径和「返回调用点」会带你回到原位置。

  1. 蓝色调用节点同时给出调用文件、行号和目标定义。子流程结束后，回到父节点继续下一步。
  2. 条件框保留成立与不成立两条路径。当前配置确定不会走的路径默认折叠；运行时才能判断的路径均保留。
  3. 循环框只展示一轮结构。预热、设备、模型层和执行图的实际重复次数没有被改成一次。
  4. 「读到这里」保存当前调用路径；「已读」按调用位置和进入路径独立记录。可导出进度备份。
  5. 源码为生成时的快照。项目更新后，在此目录运行 python3 build_flow.py --check 检查是否过期。

本图读取项目自有 C++ 源码，省略简单取值、断言和标准库内部实现；Ramulator 停在项目适配层边界。多态与函数表的多个实现是可选子流程，不表示它们全部依次执行。未进行实际运行跟踪。

同一表达式中的嵌套调用先于外层调用显示；多个参数之间若 C++ 未规定先后，图中排布仅用于阅读。异常分支和 return / break / continue 均保留退出语义。
